# 标本馆自适应基数树（ART）内存索引

面向自然博物馆标本馆“几百万件馆藏号 / 采集号 / 学名”的**前缀查找与范围浏览**场景，
用 Go 实现的自适应基数树（Adaptive Radial Tree, ART）内存索引库，附带一个
查看**分键浏览、树结构、节点规格分布、内存占用与耗时**的 Web 页面。

## 目录结构

```
art/        ART 核心库（节点、路径压缩、懒展开、指针标记、迭代器、统计、保序编码、树导出）
ref/        排好序的切片参考实现，压测中逐步对账的“事实基准”
sim/        馆藏号 / 采集号 / 学名 / 整数键的仿真数据生成
bench/      耗时与堆内存测量工具
cmd/stress  百万级压力测试与一致性对账（可复现随机种子）
cmd/server  Web 页面服务（go:embed 单二进制，无外部依赖）
```

## 八条设计要求的落实位置

| # | 要求 | 实现 |
|---|------|------|
| 1 | node4/16/48/256 四种规格，按子节点数自动升降级 | `art/node.go`：`addChild` 满则 `grow16/48/256`，`removeChild` 低于阈值（16→3、48→12、256→36，留 1 个余量防抖）则 `shrink4/16/48` |
| 2 | node16 并行比较、node48 用 256 项下标表 | `node16.findChild` 用 SWAR 一次比较 8 个槽（`hasZeroByte`，不依赖具体 CPU 指令集）；`node48.keys [256]byte` 是字节→槽位的下标表，0 表示空槽 |
| 3 | 路径压缩、单路合并、长前缀只存一段 | 每节点内联 `prefix[10]`，更长的前缀在最小叶子的完整键里核对（`prefixMismatch`/`minLeaf`）；删除后单路节点由 `collapse` 并回压缩路径 |
| 4 | 懒展开，单子树直接挂叶子 | 树根/槽位可直接挂带标记的叶子指针（`art.go` 插入时叶子相遇才展开，删除塌缩回叶子） |
| 5 | 无符号字节比较，整数/有符号数先保序编码 | `art/encode.go`：uint 大端；int 翻符号位；float 翻符号位/取反；另含 0x00 转义 + 结束符，保证任意两键不构成前缀关系 |
| 6 | 子节点指针与叶子用指针最低位区分，不额外占空间 | `art/pointer.go`：最低位 1=叶子、0=内部节点，槽位统一存 `unsafe.Pointer`，GC 仍能经 interior pointer 识别 |
| 7 | 删除后及时降级、并回压缩路径 | `removeChild` 立即降级；`recursiveDelete`+`collapse` 把单路节点并回，叶子数量归一后退化成叶子 |
| 8 | 报各节点数量与总内存，与标准库有序结构对比 | `art/stats.go` 解析口径统计；`cmd/stress` 与有序切片（`ref`）、内置 `map` 做内存/耗时对比 |

## 关键设计说明

### 保序编码与键转义（art/encode.go）

树内只认无符号字节序。整数经保序编码后字节字典序等于数值序：

- `EncodeUint64`：大端字节序本身保序；
- `EncodeInt64`：加 `2^63` 翻符号位，负数变小、正数变大；
- `EncodeFloat64`：负数按位取反、正数翻符号位。

用户键统一转义后再追加结束符：数据字节 `0x00 → 0x00 0x01`，
键结束为 `0x00 0x00`。这样任意两个键都不会构成严格前缀关系，
路径压缩与叶子懒展开无需额外的“键结束”分支，且短键恒小于以它为前缀的长键。

### 指针标记与 GC（art/pointer.go）

叶子/内部节点共用一个 `unsafe.Pointer` 槽，靠最低位区分，不增加任何字段。
Go 堆对象至少 2 字节对齐，真实指针最低位恒为 0。标记后地址落在对象内部，
GC 的 interior pointer 机制仍能让叶子保活（`TestGCWithTaggedPointers` 多次
`runtime.GC()` 后校验）。

> 注意：`go test -race` 自带的 `checkptr` 会把 `ptr|1` 这类位运算判为
> “指针指向非法分配”，这是 checkptr 对标记指针的固有限制（plar/go-art 等
> 社区库同样如此），并非数据竞争。普通 `go test` 与 `go build` 不受影响。
> `go vet` 也会对该模式报一条 `possible misuse`，属同类误报。

### 有序遍历统一走“分支字节”（art/iterator.go）

node48 的 `kids[]` 按插入顺序排列、node256 有空槽，物理槽序都不等于字节序。
因此所有遍历（First/Next/Seek/PrefixScan/统计/树导出）一律用
`firstByte / nextByte / lowerBoundByte + findChild` 按**字节值**推进，
与物理槽位彻底解耦，删除重排后也不会乱序或取到空槽。

`Seek(target)` 返回第一个 `>= target` 的键，下行时同步维护遍历栈，
命中后可直接 `Next()` 连续翻页（页面的 keyset 分页就依赖这一点）。

## 运行

需要 Go 1.26+（开发使用 go1.26.1）。

### 1. 单元测试（含随机化 property 对账）

```bash
go test ./art/ -count=1
```

`TestRandomAgainstRef` 用 3 万次混合插入/删除/查找/前缀遍历，每一步都与
`ref.SortedSlice` 对账；`TestSeek` 用 500 组随机目标核对下界定位；
`TestNodeGrowShrink` 强制节点在四种规格间反复升降级。

### 2. 百万级压力测试

```bash
go run ./cmd/stress -n 1000000 -ops 200000 -strict 30000 -strict-ops 200000 -seed 20261119
```

- 阶段一（严格对账）：3 万键池、20 万随机操作，每步与有序切片比对，
  定期做全量顺序快照与前缀对账，任何不一致立即失败退出；
- 阶段二（规模验证）：125 万键（五类键各约 25 万），报节点规格分布、
  两种内存口径、点查/前缀/遍历/删除/重插耗时，并与 map、有序切片对比。

### 3. Web 页面

```bash
go run ./cmd/server -n 200000 -addr :8080
# 浏览器打开 http://localhost:8080
```

四个标签页：

1. **分键浏览**：keyset 分页（hex 游标，保序且支持二进制键）+ 前缀过滤；
2. **树结构**：可选展示深度，节点按规格着色，显示压缩前缀与分支字节；
3. **节点规格分布**：node4/16/48/256 数量、占比、单节点字节与小计；
4. **内存占用与耗时**：ART 解析口径/GC 口径、map、有序切片估算对照，
   以及构建/点查/前缀遍历耗时。

API（键均以十六进制字符串返回，hex 字典序即原始字节序）：

```
GET /api/keys?after=<hex游标>      分页
GET /api/keys?prefix=<前缀>         前缀范围
GET /api/tree?depth=4               树结构
GET /api/stats                      节点规格分布
GET /api/memory                     内存与耗时
```

## 一次百万级实测（125 万键，种子 20261119）

- 节点：node4≈11.5 万、node16≈13.9 万、node48≈109、node256≈257，
  内部节点 25.4 万，最大深度 14、平均深度 6.77；
- ART 解析口径约 **128.6 MiB（≈107 B/键）**，有序切片同口径外推约 139.9 MiB；
- 全量有序遍历约 132 ms，明显快于重新排序的 215 ms；
- 删除 20 万键后节点自动降级、路径并回，重插后全量顺序再次对账通过。

说明：本仿真里大量是 8 字节随机整数键，路径压缩收益有限，因此 ART 对
`map` 的点查/内存并不占优（map 无序、不能做范围浏览，本就不是同类用途）。
真实馆藏号/学名共享长前缀（如 `NHM-PB-`、科属名），路径压缩会显著摊薄
内部节点开销，ART 的有序范围能力正是 map 无法提供的核心价值。

## 仿真数据（sim/sim.go）

- 馆藏号 `NHM-PB-00000001`（定宽零填充，前缀/范围友好）；
- 采集号 `XZ2003-000123`（队号 + 年份 + 流水号）；
- 学名 `科名|属名 种加词#流水号`（拉丁双名风格，# 保证唯一）；
- 无符号 / 有符号整数键（保序编码，正负混合，专门检验编码正确性）。
